## Alcance del candidato

`1.0.0-rc.1` representa el conocimiento F1 estructurado del libro completo y su distribución reproducible para consumidores. El candidato mantiene separadas la transcripción de fuente, la normalización editorial y la explicación pedagógica.

El gate global F1 automatizado cubre:

- cobertura del libro completo;
- validación del repositorio y referencias cruzadas;
- clasificación de source gaps históricos;
- presencia de FigureSpec o razón de exclusión para visuales significativos;
- inventario y procedencia de QR;
- candidatos de seguridad y su revisión documentada.

Los conflictos conocidos de la fuente se conservan como conflictos. Ningún valor se elige como ganador por inferencia.

Ninguna regla del candidato tiene estado de autoridad ejecutable de fabricación.

## Bundle reproducible

Comando canónico desde la raíz del repositorio:

```bash
uv sync --all-groups
uv run python -m carpinova_knowledge validate --root .
uv run python -m carpinova_knowledge build-book-dist --root . --book-id cpnc-2025 --out work/f1-bundle
```

Salida esperada:

- `knowledge.bundle.json`
- `figures.bundle.json`
- `lessons.bundle.json`
- `manifest.json`

El manifest debe identificar `scope=BOOK`, `book_id=cpnc-2025`, `knowledge_version=1.0.0-rc.1`, el SHA-256 canónico de la fuente, conteos de registros y hashes de los archivos generados.

La prueba automática de distribución construye el libro dos veces y exige resultados deterministas.

## Plan de revisión humana antes de 1.0.0

### Revisión técnica

Revisar con la fuente canónica exacta:

1. todos los conflictos técnicos conocidos y sus dos o más afirmaciones de origen;
2. todos los RuleSpec que puedan influir en fabricación, montaje, seguridad o selección de materiales;
3. todos los MeasurementSpec usados por reglas, lecciones o explicaciones de fabricación;
4. todas las páginas marcadas por seguridad, QR, visual pendiente o cualquier `UNRESOLVED` técnicamente relevante;
5. que ninguna afirmación candidata se haya convertido silenciosamente en autoridad universal o ejecutable.

Cada hallazgo debe registrar página/record ID, evidencia, resultado `PASS`, `NEEDS_CHANGE` o `UNRESOLVED`, y la disposición tomada. Un dato no legible o no demostrable permanece `UNRESOLVED`.

### Revisión editorial

Revisar con la fuente canónica exacta:

1. el 100 % de las páginas con conflictos, source-gap histórico, seguridad, QR o visuales significativos;
2. como mínimo una página representativa de cada batch restante;
3. fidelidad de `source_transcription` a la fuente;
4. que `normalized_text` mejore redacción sin cambiar el significado técnico;
5. que `learning_text` simplifique sin agregar datos, certezas o recomendaciones que la fuente no sostiene;
6. que toda simplificación conserve trazabilidad al ContentSpec de origen.
