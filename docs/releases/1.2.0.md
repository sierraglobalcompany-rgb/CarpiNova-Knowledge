## Interacciones source-backed

El schema de LessonSpec expone exactamente cuatro tipos de interacción:

```text
highlight
highlight_measurements
identify_parts
guided_sequence
```

`identify_parts` usa etiquetas y ubicaciones respaldadas por contenido canónico; no infiere asociaciones SVG por apariencia.

`guided_sequence` referencia contenido y MeasurementSpec canónicos de los pasos de instalación.

La validación de Knowledge falla cerrado cuando una interacción contiene referencias inválidas. Entre los guardrails verificados están:

- entity targets deben resolver;
- measurement targets deben resolver;
- `identify_parts.source_content_id` debe resolver y pertenecer al mismo lesson step;
- cada `guided_sequence.content_id` debe resolver y pertenecer al mismo lesson step;
- measurement IDs guiados deben resolver;
- el orden de la secuencia guiada debe ser único.

## Guardrails KISS / anti-ruido

Knowledge `1.2.0` no introduce:

```text
generic interaction engine
second renderer
3D / WebGL / Three.js
backend
database
AI subsystem
renderer registry
plugin architecture
CarpiNova-cell implementation
```

Se reutilizaron el schema system, validator, renderer 2D y contratos existentes. Knowledge permanece como fuente de verdad y los consumers no redefinen contenido canónico.

## Estado documental

Este release record, junto con `README.md` y `CHANGELOG.md`, cierra la desincronización documental `K12-DOC-DRIFT` una vez que el PR docs-only sea integrado y su QA post-merge sea verificado.

No se crea `1.2.0-review.md`: la evidencia de integración, QA y compatibilidad ya está concentrada aquí y en los PR/workflows auditables; duplicarla no aporta una fuente de evidencia única.
